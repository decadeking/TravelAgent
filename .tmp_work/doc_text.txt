[86] <Normal> (374字) 摘要：针对传统旅行规划依赖人工攻略、信息零散、难以结合用户偏好与实时条件做动态调整的问题，本文设计并实现一套基于 FastAPI 和 Vue3 的交互式旅行规划智能体系统。系统采用前后端分离架构，核心规划能力由 LangGraph 状态图编排，并结合函数调用与检索增强生成技术完成需求解析、行程组织与结果反思，通过 SSE 服务端推送实现分步流式输出。系统划分用户、AI 规划、工具调用与知识库等模块，提供行程生成、行程编辑、行程分享与评论、个人中心等功能，管理员可进行内容审核与运行监控。数据库采用 MySQL 存储业务数据，通过PostgreSql加pgvector插件新增向量功能，充当知识库完成向量检索提升回答准确率，降低事实性错误。测试结果表明系统响应迅速、规划结果准确，能够根据目的地、天数与偏好自动生成较合理的行程，满足实际使用需求。

[91] <Normal> (102字) The Design and Implementation of an Interactive Travel Planning Agent System Based on FastAPI and Vue3
[92] <Normal> (1465字) Abstract：Traditional travel planning often relies on manually compiled guides, while information is scattered and hard to combine personal preferences with real-time conditions for dynamic adjustment. This paper designs and implements an interactive travel planning agent system based on FastAPI and Vue3. The system adopts a front-end and back-end separation architecture. The back end provides asynchronous interfaces with FastAPI, and the front end is built with Vue3, TypeScript and Pinia. The core planning capability is orchestrated by a LangGraph state machine, combined with function calling and retrieval-augmented generation to complete requirement parsing, itinerary organization and result reflection, and realizes step-by-step streaming output through SSE. The system is divided into user, AI planning, tool invocation and knowledge base modules, providing itinerary generation, editing, sharing and comments, personal center and other functions, while administrators can conduct content review and operation monitoring. MySQL stores business data, and Redis implements rate limiting, idempotency and session caching, while optimistic locking and transactions guarantee consistency. Vector retrieval and similarity threshold filtering improve answer accuracy and reduce factual errors. Test results show that the system responds quickly and produces reasonable itineraries according to destination, days and preferences, meeting practical requirements.

[99] <Normal> (136字) 随着生活水平提高和节假日增多，自助旅行逐渐成为主流出行方式，但多数游客在制订行程时仍依赖搜索引擎、游记与社交平台，需要反复查阅大量信息才能拼凑出可行方案，效率低、体验差。许多在线旅行产品虽然提供了酒店、交通与景点预订，却缺少能够结合用户时间、预算与兴趣自动编排行程的能力。
[100] <Normal> (124字) 与此同时，大语言模型在自然语言理解、知识问答与工具调用方面表现出较强能力，为智能化的行程规划提供了新思路。将大模型与检索增强生成、实时工具调用相结合，可以让系统在理解用户模糊需求的基础上，主动联网查询天气、景点与位置信息，最终生成结构化的行程安排。

[103] <Normal> (12字) 1.2.1 国内研究现状
[104] <Normal> (554字) 国内在大模型与智能问答应用方面的研究进展迅速，大模型进入应用层之后，如何让它真正“会用工具”成了国内研究绕不开的问题。朱宇豪、戴琳琳、景辉等围绕铁路出行场景，把需求理解、资源检索与结果生成串成一条完整链路，构建出可落地的行程规划与推荐智能体[1]，说明在业务边界清晰的领域，「拆分任务—调用资源—汇总输出」这套做法确实能跑通。而真正落到多工具并存的场合，问题就转到调用是否稳定上：江志英、黄震宇、宋晨炜等提出基于思维代码的提示方法，用显式的思维结构约束模型拆解任务的顺序，让模型在多工具环境下少走弯路，工具调用的一致性与成功率随之改善[2]。郭先会、张梦姣、马军等则从更宏观的层面梳理了智能体的构建路径，把角色设定、记忆机制、任务规划与工具调用归纳为几个关键环节，认为单点优化之外更需要整体架构上的配合[3]。车万翔、窦志成、冯岩松等对模型时代自然语言处理面临的挑战作了系统梳理，同样把工具使用、规划与多轮交互列为需要重点回应的议题[4]，这与前面几项工作的关注点恰好互为印证。工程侧的变化同样明显，前后端分离的 Web 架构配合检索增强生成搭建知识库问答，已成为国内智能问答产品的常见组合；朱俊仪、朱尚明以本地知识库为例，完整给出了检索、重排与生成的实现路径，也提示了检索质量对最终答案的决定性影响[5]。
[105] <Normal> (12字) 1.2.2 国外研究现状
[106] <Normal> (581字) 国外对“推理”与“行动”能否合流的讨论起步更早，也更成体系。Jason Wei 等提出的思维链提示，让模型在给出答案之前先把中间推理写出来，复杂任务上的表现因此明显提升[6]，这为后来的「边想边做」埋下伏笔。沿着这条线索，Shunyu Yao 等把推理轨迹与实际行动交错起来，模型一边思考一边调用工具，再依据返回结果修正下一步，形成 ReAct 范式[7]，它至今仍是多数智能体的基本骨架。与推理并行的另一条路是知识获取：Patrick Lewis 等提出检索增强生成，先把外部文档检索出来再拼接进上下文，缓解了模型凭空作答与知识老化这两个老问题[8]。Timo Schick 等的 Toolformer 更进一步，让模型自己学会在合适的位置插入工具调用，工具不再完全依靠人工编排[9]；Yujia Qin 等则把可用工具扩展到上万条真实 API，用 ToolLLM 训练模型在大量接口中挑选合适的那个[10]。工具一多、约束一多，规划是否还稳得住就成了新问题：Jian Xie 等构建 TravelPlanner 基准，用贴近真实的多日行程任务考察智能体在多约束条件下的规划水平[11]；Binfeng Xu 等的 ReWOO 从效率入手，把推理与观测拆开，减少不必要的模型调用[12]。这些工作各有侧重，共同构成了交互式行程规划智能体可以直接借用的技术基础。

[180] <Normal> (91字) 页面响应：正常网络下普通接口响应控制在 3 秒以内，首页与行程列表的首屏数据加载在 1 秒以内；行程生成属于长耗时链路，通过 SSE 先返回进度与中间结果，不要求一次性返回完整行程。

[182] <Normal> (93字) 流式输出：行程生成的解析需求、查询景点、查询天气、整理行程等中间步骤通过 SSE 分步推送，前端步骤条实时推进，避免页面长时间空白；连接中断后可携带事件游标续传，既不丢步骤也不重复规划。

[185] <Normal> (123字) 密码加密：用户密码经加盐哈希后存储，数据库不保存明文，即使库被拖走也难以还原；登录失败时统一提示“账号或密码错误”，不区分是账号不存在还是密码错误，避免被用来枚举账号。登录鉴权：后端使用 JWT 校验身份，未登录用户禁止访问行程生成等受保护接口；
[186] <Normal> (85字) 角色权限：普通用户与管理员接口分别挂载，后端在进入业务逻辑前即校验角色，越权请求直接拦截，不依赖前端隐藏按钮；会话记录按所属用户校验，防止借用他人的会话标识读取对话内容。
[187] <Normal> (70字) 内容管控：分享动态经管理员审核后才对外展示，违规内容可驳回下架；被拉黑用户禁止发布、评论、点赞等社区互动，拉黑原因与时间同步记录并通知本人。
[188] <Normal> (85字) 登录鉴权 ：后端以 JWT 校验身份，未登录用户禁止访问行程生成、编辑、删除等受保护接口；令牌在服务端留有会话记录，支持过期失效与主动吊销，用户改密或被拉黑后可立即失效。
