## 附：第二轮修复（针对"配置密钥后仍输出模板数据"的反馈）

### 一、先定位真因（不是"文档造假"，是链路真有问题）

对照代码与生产日志，找到两处**真实缺陷**：

1. **槽位不全即短路到 clarify 模板**：原 `graph._slots_complete()` 要求「目的地+天数+预算」三者齐全，
   缺一就跳过后面的 plan/tool_call/RAG，直接输出一句固定中文模板
   （"为了给你规划行程，我还需要知道：…"）。用户没同时说天数和预算时，**全程不会调用大模型、不检索 RAG、不调工具**——
   这正是"还是模版数据"的根因。
2. **目的地抽取只认 6 个城市**：`poi.json` 只有成都/北京/上海/杭州/西安/厦门，
   用户提到其他城市（或"去机场"这类词）时抽不到目的地，进一步触发上面的模板短路。

### 二、本轮修复

| 问题 | 修复 | 位置 |
|---|---|---|
| 槽位不全就输出模板 | 只要有目的地就进入规划：天数默认 3、预算未填按不限；**仅当目的地缺失才反问** | `core/graph.py::_slots_complete` |
| 反问是死模板 | 反问改由模型生成自然话术（有密钥时），离线才回落本地模板 | `core/nodes.py::clarify` |
| 目的地只认 6 城 | 目的地识别扩展到 38 个内置城市 + 英文别名 + 「去X」启发式（并过滤"机场/酒店"等非地名） | `core/nodes.py::_extract_city` |
| 提醒意图被当成行程规划 | 新增 `reminder` 分支：识别「提醒/别忘了」等意图时直接建提醒，不强行规划行程 | `core/graph.py`、`nodes.reminder` |
| 模型漏填工具参数导致校验失败 | 用已知槽位（目的地/天数/预算）自动补全工具参数 | `nodes._fill_from_slots` |
| 用户看不出是真模型还是模拟 | `done` 事件新增 `engine/model_used/rag_hits/tools/degraded`，前端在对话尾部标注「真实模型 xxx · RAG 引用 N 条 · 工具 N 个」 | `service.py`、`PlanView.vue` |
| 离线 mock 看不到提醒 | mock 增加提醒意图分支（无密钥也能演示） | `llm/adapter.py` |
| 会话已带目的地时提醒失效 | 提醒意图只看**本轮原话**，不被上一轮的目的地槽位带走 | `core/graph.py::_after_intake` |
| 生产托管下 /login 等前端路由 404 | 改为挂载 `/assets` + 通配路由回退 `index.html`（SPA history 模式） | `app/main.py` |
| 「真实/离线」标识误报 | mock 不再回显展示模型名，改为显式 `LLMResult.provider`，仅 `openai` 记 real | `llm/adapter.py`、`service.py` |

### 三、用户三项诉求的落实

| 诉求 | 结论 |
|---|---|
| **API Key 是否明文保存在 env/文件** | 原先：`.env` 中 `LLM_API_KEY` 为空（服务端默认不存密钥），但**用户/管理员在界面填的密钥以明文存 MySQL**。本轮改为 **Fernet 加密落库**（`enc:` 前缀、读时解密、兼容历史明文），并写了迁移脚本把既有明文升级为密文（已执行：user8 密钥 35→144 字符密文）。`.env` 仍只放非敏感运行参数。 |
| **为什么显示过关但还是模板数据** | 见上文「一、真因」——是 clarify 短路 + 目的地抽取过窄两个真实缺陷，不是文档造假；本轮已修，并加了端到端验证脚本证明 **engine=real / RAG 命中 / 工具调用**。 |
| **工具是否正常（定位/天气/时间/提醒）** | 天气=Open-Meteo 实时；路线=OSRM 真实；定位=内置 38 城坐标表 + **Nominatim 真实地理编码**（冷门地名）；时间=服务器真实时钟 `get_current_time`；提醒=**新增 `set_reminder`**（自然语言时间解析 → MySQL 落库 → 后台 30s 调度转站内通知 → 前端铃铛）。 |

### 四、知识库更新

- `data/knowledge_base.json`：13 → **25 篇**（新增重庆/三亚/丽江/桂林专题 + 4 篇通用更新篇）。

### 五、遗留说明（如实记录）

1. 真实模型在 FC 循环里会重复调用工具（本次观测 6 轮内约 20 次调用）。功能正确但偏浪费，
   已由 `max_loops=6` 封顶；后续可在 system prompt 加"同一工具同参数不必重复调用"的约束。
2. 用户级密钥加密依赖 `SECRET_ENCRYPTION_KEY`（未设置时由 `JWT_SECRET` 派生）。
   **生产环境应显式设置**，否则更换 JWT_SECRET 会导致旧密文无法解密。
3. 提醒调度为进程内 asyncio 循环（30s 一次），多副本部署时需改为单实例或加分布式锁去重。
4. 管理员「一键为所有人配置」密钥/向量模型：目前管理员全局配置对所有用户生效（用户未自配时用全局），
   尚无"批量下发到每个用户"的独立入口；用户自配密钥优先于全局。

| 行程提醒 | `agent_service/reminders.py` | 到期提醒转站内通知 |
| 我的收藏 / 我的评论 | 从个人中心迁移 | `GET /api/messages` 之外的 tab 复用原有接口 |

  并以一行入口卡片指回消息中心。

### 二、规划页会话持久化

问题：切到其他页面再回来，"思考中的残缺行程"会丢——原因是 `onBeforeUnmount` 里无条件 `abort()` 了流式请求，
后端随之取消规划任务，状态没落盘。

修复：
- 会话 id 与轻量快照写入 `localStorage`（`ta_active_session` / `ta_active_snapshot`）；
- 切页时**若仍在规划中则不 abort**，让后端把这一轮跑完并写入 checkpointer 状态；
  回到页面先用快照即时渲染，再 `restoreSession` 与服务端对齐；
- 只有用户主动点「新建会话」（`resetSession`）才清空本地记录。
