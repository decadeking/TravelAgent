# 总体架构与技术栈

---

## 一、分层架构

系统自上而下分为五层：

```
┌─────────────────────────────────────────────────────────────┐
│ 接入层   Nginx：SSL 终结 · 静态资源 · 负载均衡(least_conn)      │
├─────────────────────────────────────────────────────────────┤
│ 网关层   API Gateway：JWT 鉴权 · 双层限流 · 路由 ·             │
│                      trace_id / request_id 注入 · 统一错误格式  │
├─────────────────────────────────────────────────────────────┤
│ 服务层   user-service · trip-service · agent-service ·         │
│          tool-service · admin-service                          │
├─────────────────────────────────────────────────────────────┤
│ 数据层   MySQL(业务事实) · Redis(会话/缓存/锁/幂等) ·           │
│          PostgreSQL+pgvector(向量检索)                          │
├─────────────────────────────────────────────────────────────┤
│ 外部依赖 大模型 API · 天气/地图/POI API（慢且不可靠 → 防护重点）  │
└─────────────────────────────────────────────────────────────┘
```

**开发/演示形态**：由 `backend/app/main.py` 单进程装配全部服务（「逻辑微服务、轻量部署」），数据用 SQLite、KV 用内存、LLM 用 mock —— 一条命令即可运行与测试。
**生产形态**：每个服务独立 Dockerfile + 独立容器，`deploy/docker-compose.yml` 编排 nginx/gateway/各服务/MySQL/Redis/pgvector/Jaeger/Prometheus/Grafana。

---

## 二、服务拆分与职责

| 服务 | 核心职责 | 关键技术 | 对外接口 |
|---|---|---|---|
| gateway | 统一入口、JWT 鉴权、限流、路由、注入 trace_id | FastAPI 中间件 + 依赖注入 | 所有外部请求 |
| user-service | 注册登录、偏好管理、Token 配额 | FastAPI、SQLAlchemy、JWT、bcrypt | `/api/auth/**`、`/api/users/**` |
| trip-service | 行程/天/行程项 CRUD、乐观锁 | FastAPI、SQLAlchemy | `/api/trips/**` |
| agent-service | 会话管理、状态图编排、SSE、LLM 调用、RAG、记忆 | StateGraph、SSE、httpx | `/api/agent/**` |
| tool-service | 天气/景点/路线/预算/搜索统一封装 + mock | FastAPI、本地 JSON | `/api/tools/**` |
| admin-service | 指标、熔断状态、链路、SSE 连接、故障演练 | FastAPI | `/api/admin/**` |

**tool-service 独立成服务的三个理由**：① 工具被多场景复用（行程详情页也查天气）；② 第三方限流/缓存/超时要统一治理；③ 答辩时可一键切 mock 数据源，对上层透明。

## 四、状态图设计

**状态（State）五组字段**：`messages`（对话历史）、`slots`（槽位：目的地/天数/预算/偏好）、`plan_draft`（行程草稿）、`tool_results`（工具结果）、`revision_count`（修订计数）。

**六个节点与条件边**：

```
intake ──槽位完整?──┬── 否 → clarify → END
  │                 └── 是 → plan → tool_call → reflect ──自检通过?──┬─ 否(≤3次) → plan（修订回环）
  │                                                                  └─ 是 → respond → END
```

- `intake`：意图识别与槽位抽取
- `clarify`：槽位缺失时逐项反问（绝不让模型脑补）
- `plan`：RAG 检索 + 生成行程骨架与工具查询请求
- `tool_call`：Function Calling 循环，获取天气/景点/路线/预算事实
- `reflect`：自检预算超支、路线顺序、时间冲突；不合格则回到 plan
- `respond`：流式输出结语

**三个关键机制**：① `checkpointer` 每节点后把状态写入 Redis/KV → 多轮会话与断线恢复天然成立；② `interrupt` 语义（`reflect → respond` 前给出 `plan_update`）实现 human-in-the-loop，用户下一轮消息即触发修订；③ `revision_count` 给反思循环封顶（≤3），防止烧 Token。

## 五、前端交互与 SSE 协议

**技术选型**：Vue 3 + Vite + TypeScript + Pinia + Vue Router；SSE 用原生 `fetch` + `ReadableStream` 手动解析（支持 POST + 鉴权头）；组件样式自研。

**页面结构**：登录/注册 → 行程列表 → **规划对话页（核心：左对话流 + 右行程实时预览）** → 行程详情 → 个人中心。头像固定于**右上角**，下拉含设置、偏好、Token 用量、退出登录。

**SSE 事件协议**（`POST /api/agent/chat`，全系统唯一 SSE 接口）：

| 事件 | 载荷 | 前端行为 |
|---|---|---|
| `meta` | session_id、trace_id | 记录会话 |
| `token` | 文本片段 | 打字机追加到 AI 气泡 |
| `tool_call` | 工具名与参数 | 弹过程卡片「正在查询天气…」 |
| `tool_result` | 结果摘要 | 过程卡片更新为完成态 |
| `plan_update` | 行程 JSON | 增量刷新右侧预览 |
| `memory` | 已回写的偏好 | 提示「已记住偏好」 |
| `ping` | 心跳 | 忽略 |
| `done` | token 用量、session_id | 结束流式，恢复输入框 |
| `error` | 错误码与信息 | 错误横幅 + 重试 |

## 六、技术栈总表

| 层面 | 技术 | 承担角色 |
|---|---|---|
| 前端基座 | Vue 3、Vite、TypeScript、Pinia、Vue Router | 页面、状态与路由 |
| 前端交互 | 原生 fetch + ReadableStream（SSE）、自研组件样式 | 流式对话、行程预览 |
| 后端框架 | FastAPI、Pydantic v2、Uvicorn | 异步 API 与校验 |
| 数据与存储 | SQLAlchemy 2.0、SQLite/MySQL 8、内存 KV/Redis 7 | 业务数据、缓存、锁与幂等 |
| Agent 编排 | 自研 StateGraph（对齐 LangGraph 语义） | 状态编排、human-in-the-loop |
| 模型调用 | httpx + OpenAI 兼容协议（DeepSeek/通义）；mock 兜底 | 结构化输出、工具调用 |
| RAG | 结构切片 + 哈希 Embedding（可选 OpenAI Embedding）+ 内存向量库（对齐 pgvector/HNSW） | 静态知识检索与引用 |
| 稳定性组件 | 自研 熔断器 / 重试 / 幂等 / 分布式锁 + KVStore(Lua) | 限流、重试、熔断、锁、幂等 |
| 可观测性 | 结构化 JSON 日志、轻量 Span 追踪（对齐 OTel/Jaeger）、Prometheus 文本指标 | 日志、追踪、指标 |
| 部署 | Docker、Docker Compose、Nginx（K8s 展望） | 本地集群模拟与负载均衡 |

## 七、部署视图

- **开发环境**：`python backend/run.py` + `npm run dev`（前端 5173 代理到后端 8000）。
- **生产环境（配置齐备）**：`deploy/docker-compose.yml` 拉起 nginx、gateway、五个服务、MySQL、Redis、pgvector、Jaeger、Prometheus、Grafana；Nginx 以 `least_conn` 转发，agent-service 配 2 副本分担 SSE 长连接。
- **弹性伸缩展望**：K8s Deployment + HPA（按 SSE 连接数或 QPS 扩缩容），Ingress 统一入口。
